# 首次下载复核：四个工具怎样验过

[文档目录](README.md) · [Windows 下载与启动](12_windows_quickstart.md)

2026-10-13，从公开 GitHub 重新下载 v0.6.3 Windows 完整包，校验 SHA256 和全部 ZIP CRC，解压到新的含空格目录。测试进程只保留 Windows 系统路径，另设空的用户缓存和临时目录；Python、科学依赖、CPU/GPU 程序均从下载包定位，没有安装 Python、Anaconda、编译器或 CUDA Toolkit。

这是同一台 Windows 10 x64 / Quadro P5000 机器上的独立运行环境测试，不是新装系统虚拟机或其他型号电脑的测试。Windows 与现有 NVIDIA 驱动属于操作系统条件；没有 NVIDIA GPU 时使用 CPU。硬件选择见 [电脑适配指南](12_windows_quickstart.md#3-不知道自己的电脑能不能用-gpu)。

## 实际操作与结果

| 工具 | 从界面操作的流程 | 已完成检查 |
|---|---|---|
| 散斑 | 载入真实 CRL → 浏览选择参考图 → 预览 → CPU/GPU WXST；切换 WSVT → 100 对 CRL → CPU/GPU运行 | 四种组合成功，实际 EXE 哈希对应随包程序，492×492 相位有限，标定记录正确 |
| 光栅 | 试用示例 → 展开数据文件 → 载入本次输入与参数 → FFT预览 → 再运行 | 两次成功；解析相位 RMSE 约 1.37e-13 rad |
| Hartmann | 试用示例 → 复用配置 → 网格预览 → 再运行 | 两次成功；已知质心平移最大误差约 2.66e-13 px |
| 完整 Zernike | 导入随包 config.json → 浏览选择示例目录 → 预览 → 50项分析 → 下载系数CSV | 全部50项、PV/RMS、曲率、五种数值图和TIFF报告齐全；拟合残差 RMS 约3.19e-16 rad |

散斑导出配置和 Zernike 系数表通过浏览器下载动作检查，结果不是只在服务器上存在。后台停止、重启后，四个页面分别恢复4、2、2、1条任务记录，共9次运行。200个CRL裁剪文件和147个保留原生源码的哈希均核对一致。

上述时间与数值用于记录本次操作，不是性能基准或真实CRL精度真值。光栅、Hartmann和已知Zernike属于明确标注的解析控制；真实透镜数据用于散斑流程。

## v0.6.4 修正的首次使用问题

1. 光栅、Hartmann、Zernike 的“使用指南”改为对应的完整操作页。
2. 完整 Zernike 页面明确说明“导入配置 → 浏览示例目录 → 预览”，不再引导点击不可用的示例按钮。
3. 散斑转完整 Zernike 从成功结果的 `metadata.json` 传递标定：eV → keV、m → µm。CRL应显示12.4 keV和1.625 µm。不使用后来修改但尚未计算的表单；缺标定时提醒手动填写。
4. 接入新相位时隐藏上一份报告，显示“等待分析新相位”。
5. 文档补充四个窗口同一时间只运行一个任务；等待后再运行即可。
